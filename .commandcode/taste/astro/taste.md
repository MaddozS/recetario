# astro
- Avoid relying on data-* attributes passed to the Button component for JS selectors — Astro's Button may not forward them to the DOM. Use button[type="submit"] or other native selectors instead. Confidence: 0.70
- Avoid importing from server-side barrel packages (e.g., @recetario/billing) in Astro client-side <script> blocks — they may re-export Node.js-only modules (Stripe, dotenv, pg) that silently crash the entire script. Inline simple functions instead. Confidence: 0.70
- When middleware needs multiple independent API calls (e.g., credential-status, subscription, preferences), parallelize them with Promise.all + .then() ok/error discriminators instead of serial await+try/catch chains. This reduces waterfall latency in the critical request path. Confidence: 0.75
- Use Astro.locals as a caching layer between middleware and pages: fetch shared data (preferences, subscription) once in middleware and store on locals, then pages read from locals with a ?? fallback to re-fetch only when the cache is cold. This avoids duplicate API calls on every page render. Confidence: 0.80
- In Astro ClientRouter setups where client-side <script> blocks re-execute on every page swap, use dataset guard flags (e.g., dataset.sncBound === "1") to prevent duplicate event listener bindings. These guards are more reliable than removeEventListener or checking listener counts, since ClientRouter swaps can leave stale listeners behind. Confidence: 0.70
- When implementing skeleton-based loading for Astro ClientRouter navigations, use the `astro:before-swap` lifecycle event to replace the content slot's innerHTML with skeleton markup before the View Transitions snapshot is captured. This is the only reliable way to prevent old-page flash — overlay and display:none approaches fail because the View Transitions API captures the DOM snapshot independently of CSS visibility. Confidence: 0.85
