# cloudflare-workers
- Pin @astrojs/cloudflare to ^13.x (e.g., 13.7.0) when using Astro 6 — the v14 adapter requires Astro 7. Confidence: 0.75
- Patch the generated Prisma client (client.ts) to guard import.meta.url with a typeof check before calling fileURLToPath — in Workers runtime it can be undefined. Use a post-generate script. Confidence: 0.70
- Add workerd: true to allowBuilds in pnpm-workspace.yaml — Wrangler depends on it and pnpm blocks it by default. Confidence: 0.70
- In local dev, proxy /api/* from Astro's Vite dev server to the Hono API worker (e.g., http://127.0.0.1:8787) so both can run together through Turbo. Confidence: 0.65
- List all workspace packages in vite.ssr.noExternal (in astro.config.mjs) so Vite bundles them through its SSR pipeline instead of loading them raw in the Workers sandbox — otherwise @prisma/client's createRequire leaks the module global that doesn't exist in workerd. Confidence: 0.70
- When creating Vite plugins to shim virtual modules, use both resolveId (with \0 prefix) and load hooks — the load hook alone may not intercept bare specifier imports in Vite v7's SSR dev runtime. Confidence: 0.70
- When using `withFreshDb` (or any per-request PrismaClient factory) in Workers, the fresh instance must be explicitly threaded through to every downstream database call. Functions that import the singleton `prisma` directly will use the wedged pool and cause the request to hang — even if a fresh connection is sitting unused in the handler scope. The `_prisma` naming convention (underscore = intentionally unused parameter) is a code smell that flags this bug. Pattern: add optional `db?: PrismaClient` params that default to the singleton, and pass the fresh instance from the handler. Confidence: 0.80
- Wrangler cannot resolve subpath imports (e.g., `better-auth/crypto`, `@better-auth/utils/password`) from packages that aren't direct dependencies of the worker. When a worker needs a utility from a transitive dependency, create a thin re-export file in an internal workspace package that lists the dependency directly, then import from the internal package (e.g., `packages/auth/src/hash-password.ts` → `export { hashPassword } from "better-auth/crypto"` → consumed as `@recetario/auth/server`). Do NOT inline the crypto yourself — the hashing algorithm must match what the framework uses (e.g., scrypt vs PBKDF2) or `verifyPassword` will break. Confidence: 0.75
- Cloudflare Worker secrets are managed through a centralized `.env.cloudflare` file (all secrets in one place) with a `scripts/secrets-map.json` dispatch map that routes each secret to the correct worker(s), then pushed via `scripts/sync-cloudflare-secrets.mjs`. Run the sync script from `apps/api` (where `wrangler` is a real dependency — its preCheck fails from the repo root). Do NOT set secrets manually per-worker in the Cloudflare dashboard — use the script. Confidence: 0.75
- Wrangler authenticates via `CLOUDFLARE_API_TOKEN` + `CLOUDFLARE_ACCOUNT_ID` loaded from `.env` (e.g., `set -a; source .env`), not interactive `wrangler login` OAuth. When wrangler reports auth errors, check for those env vars first. Confidence: 0.65
- When adding a new environment variable that Workers runtime code reads from `process.env`, it MUST be listed in `REQUIRED_ENV_KEYS` in `packages/config/src/env.ts` — otherwise `syncEnvBindings` won't copy the Cloudflare binding into `process.env` and the variable will be `undefined` at runtime. The `console.assert` that guards the array length must also be updated to match. Confidence: 0.80
- A Cloudflare service binding (Worker→Worker) forwards the request preserving the **original `Host` header**, not the target service's host. Any upstream host-allowlist check therefore sees the calling worker's public host, so the upstream's allowed-host config (e.g., `INTERNAL_API_HOST`) must match the calling worker's public host per environment (or be unset) — otherwise the upstream rejects with a host-not-allowed 403. Confidence: 0.6
