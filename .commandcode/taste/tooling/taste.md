Keeping the cache in a separate directory (e.g., `../.vite-cache/web`) and gitignoring it lets the cache survive `pnpm install` and workspace restructures. Confidence: 0.70

- The e2e stub (`apps/web/test/e2e/support/stub-api.mjs`) is extended per domain with in-memory state plus deterministic QA fixtures — `POST /api/__qa/<domain>/reset` to seed and `GET /api/__qa/<domain>/state` to assert server-side effects (e.g. counting POST attempts, or capturing the last PATCH body in a `last<Resource>Patch` field) — with shaping helpers that mirror Hono's responses exactly (including required fields like `recipeId` that the shared Zod schemas validate). Do NOT touch the default seeds earlier specs depend on (their expected numbers move otherwise): each new spec seeds its own record via `reset`, so tests stay independent and existing specs don't break. It also enforces the real upstream's strict request contract so the suite fails if the client transport regresses: the CSRF guard must compare `x-csrf-token` against the `csrf_token` cookie (parity with `validateCsrf`, not mere presence — checking presence alone lets a sync/expiry regression pass falsely) and must be applied to recipe/ingredient mutations too, not only the auth/stripe/preferences domains. It likewise enforces trusted `Origin`, `content-type: application/json` on Better Auth mutations and replies the same 415 `UNSUPPORTED_MEDIA_TYPE`, and it serves `GET /api/csrf` (re-emitting the cookie while preserving its value) with a `mintAttempts` counter so specs can assert the client only requests a token when it is missing. Confidence: 0.6
- Playwright's API request context (`request.get`) follows redirects by default, so an SSR 302 shows up as a 200; assert redirects with `maxRedirects: 0` to see the real status and `location`. Confidence: 0.6
- The e2e stub is a single process for the whole suite: an unhandled error in one handler (e.g. seeded recipes missing a newly-required field) crashes it and cascades failures into unrelated specs (relay, shell). Keep handlers defensive and normalize seed data for backwards compatibility. Confidence: 0.6
- `agent-browser` has no standalone `resize`/`viewport` command — use `agent-browser set viewport <w> <h>` — and `screenshot` writes relative to the process cwd, not the shell's, so pass absolute paths, `screenshot '<selector>'` captures a single element while `screenshot --full` captures the whole page, and `set viewport <w> <h> [dpr]` accepts an optional third argument for device pixel ratio (`set viewport 1100 820 2` yields 2× captures). Cookies need an explicit `--url http://localhost:4321` (without it `cookies set` fails with "Invalid cookie fields"), and to QA a different theme set the `kitchcalc-theme` cookie — merely toggling the `dark` class leaves the previous theme's accent variables applied and falsifies the captures. Confidence: 0.6

- In a Nuxt app the test scripts must prepare Nuxt themselves: both Vitest and the Playwright fixture transform specs/build the app with the app `tsconfig`, which references the generated `.nuxt/tsconfig.*`. In a clean checkout (CI) that folder does not exist, so every spec fails with `Failed to load tsconfig '.nuxt/tsconfig.app.json'` and the Playwright fixture even retries the failed build per test (~150 failed builds, ~10 min job). Prefix the scripts with `nuxt prepare` (`test`, `test:e2e`, like `type-check`) so they are self-sufficient. Confidence: 0.7
- An axe/contrast sweep cannot be settled by zeroing animation/transition durations: a transition already in flight keeps its animated value, which overrides even `opacity: 1 !important`, so a slow runner measures mid-animation colors and reports a false `color-contrast` (e.g. 1.62:1 on a hero CTA). Cancel instead (`animation: none !important; transition: none !important`) and then wait for `document.getAnimations().length === 0`; the failure is timing-dependent, so reproduce it with CPU throttling (`Emulation.setCPUThrottlingRate`) rather than by re-running idle locally. Confidence: 0.65
- axe (axe-core 4.13 via `@axe-core/playwright`) analyses the _whole_ document: its `isVisibleOnScreen` only drops elements off-screen horizontally or `position: fixed` past the bottom edge, so a plain `analyze()` at the top of the page is not blind to the fold. What it misses is _state_: the landing's `a[data-spy-active]` (the node the review caught at 3.54:1) only exists while its section is in the viewport, so an honest sweep scrolls slice by slice and unions the findings of every slice — "scroll down then back to top before `axe.run`" reopens the hole. Cost: ~11 axe runs per page (≈10 s on `/`), so keep the sliced sweep only for surfaces with scroll-driven state (auth/private/accent suites keep a single settled scan). Confidence: 0.6
- Chromium keeps the original color function in the computed value of dark-theme tokens: `getComputedStyle(el).color` returns `oklch(…)` (and `color-mix`-derived backgrounds come out as `oklab(…)` with alpha), so any test/probe doing color math needs a real CSS Color 4 parser (oklch/oklab → linear sRGB, then the sRGB transfer curve). A regex for `rgb()` silently measures black, and applying the linear→sRGB curve to an already gamma-encoded `rgb()` double-gammas (lightens) the color. Confidence: 0.55
