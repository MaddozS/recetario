- Do NOT use `graphify` (the code-graph query tool) — the user says it is not correctly configured yet. Explore the codebase directly instead. Confidence: 0.8
- In pnpm monorepos, move Vite's dependency-optimization cache (`vite.cacheDir`) outside `node_modules/` — pnpm restructures `node_modules` on dependency changes, which invalidates cached SSR module paths in `.vite/deps_ssr/` and causes "file does not exist in optimize deps directory" errors. Keeping the cache in a separate directory (e.g., `../.vite-cache/web`) and gitignoring it lets the cache survive `pnpm install` and workspace restructures. Confidence: 0.70
- Prefers keeping source directories free of `tsc --build` artifacts — `.d.ts`, `.d.ts.map`, `.js`, and `.js.map` files should not litter the source tree alongside `.ts` sources. Runtime-required generated code (e.g., `prisma generate` output in `prisma/generated/`) is fine, but stale build output from a missing `outDir` or `declaration: true` config should be cleaned proactively. Confidence: 0.90
- For workspace packages consumed as raw `.ts` via their `exports` field (not pre-compiled to `dist/`), the `build` script should use `tsc --noEmit` for type-checking only — never `tsc --build`, which always emits `.js` files regardless of `declaration` settings. Confidence: 0.85

Confidence: 0.6
- In `apps/web` dev, the `/api/**` relay resolves `INTERNAL_API_URL` from the generated `.dev.vars` (wrangler proxy) with higher precedence than an inline env var — to point the dev server at the e2e stub, start the stub on port 8787 (`STUB_API_PORT=8787 node test/e2e/support/stub-api.mjs`). Confidence: 0.6

- The e2e stub (`apps/web/test/e2e/support/stub-api.mjs`) is extended per domain with in-memory state plus deterministic QA fixtures — `POST /api/__qa/<domain>/reset` to seed and `GET /api/__qa/<domain>/state` to assert server-side effects (e.g. counting POST attempts, or capturing the last PATCH body in a `last<Resource>Patch` field) — with shaping helpers that mirror Hono's responses exactly (including required fields like `recipeId` that the shared Zod schemas validate). Do NOT touch the default seeds earlier specs depend on (their expected numbers move otherwise): each new spec seeds its own record via `reset`, so tests stay independent and existing specs don't break. It also enforces the real upstream's strict request contract (CSRF token/origin, `content-type: application/json` on Better Auth mutations, replying the same 415 `UNSUPPORTED_MEDIA_TYPE`) so the suite fails if the client transport regresses. Confidence: 0.6
- Playwright's API request context (`request.get`) follows redirects by default, so an SSR 302 shows up as a 200; assert redirects with `maxRedirects: 0` to see the real status and `location`. Confidence: 0.6
- The e2e stub is a single process for the whole suite: an unhandled error in one handler (e.g. seeded recipes missing a newly-required field) crashes it and cascades failures into unrelated specs (relay, shell). Keep handlers defensive and normalize seed data for backwards compatibility. Confidence: 0.6
