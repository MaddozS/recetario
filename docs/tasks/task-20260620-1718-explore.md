## Technical Steps

1. **Load skills**: `graphify` (mandatory for codebase queries). Optionally `prisma-client-api` if reading the schema requires context.

2. **Run graphify queries** to map the codebase (max 3 queries):
   - Query 1: "What depends on src/lib/db barrel — which files import from @/lib/db"
   - Query 2: "Better Auth setup and middleware flow"
   - Query 3 (optional): "Stripe routes and webhook flow"

3. **Read critical files** listed in "Files Involved" above. For each file, note:
   - Astro-specific imports (Astro.*, Astro.locals, Astro.request, Astro.params, APIContext)
   - Cross-package dependencies (which other src/lib/* files it uses)
   - External dependencies (which npm packages)
   - Whether it uses environment variables (process.env, import.meta.env)
   - Whether it touches `Astro.locals.user` / `Astro.locals.session` / `Astro.locals.subscription`

4. **Identify coupling points**:
   - Files that import from both `Astro` and `prisma` (e.g., middleware)
   - Files that mix UI rendering with data fetching (Astro `.astro` frontmatter)
   - Files that mix server-only logic with client-side code (e.g., `auth-client.ts` vs `auth.ts`)

5. **Map the refactor target**:
   - For each of these 5 proposed packages, list exactly which files would move:
     - `packages/db/` — `src/lib/db/*` + `prisma/` + `src/lib/prisma.ts`
     - `packages/auth/` — `src/lib/auth.ts` + `auth-client.ts` + `csrf.ts` + `csrf-client.ts` + `rate-limiter.ts` + `password-validation.ts` + `password-reset.ts` + `src/middleware.ts` (or part of it)
     - `packages/billing/` — `src/lib/stripe.ts` + `src/lib/db/billing.ts` (move out of db) + `src/lib/subscription.ts` + `plans-config.ts` + `src/pages/api/stripe/*` (or keep in web)
     - `packages/ui/` — `src/components/ui/*` + Tailwind preset + global.css tokens
     - `packages/types/` — Zod schemas (currently not present, to be created)
     - `packages/config/` — `tsconfig.json` (extended base) + `eslint.config.js` (extended base) + `prettier` config
   - For each, note: would it introduce a circular dependency? Would it need a runtime adapter (e.g., for env vars)?

6. **Identify tech debt that affects the refactor**:
   - `src/lib/auth.ts` — does it import from `prisma` directly? If so, the auth package will need `@recetario/db` as a dep
   - `src/lib/stripe.ts` — does it import from `prisma`?
   - `src/middleware.ts` — does it import from `prisma` or `auth`? This will likely stay in `apps/web`
   - `src/lib/db/billing.ts` — does it import from `stripe`? If so, billing should move to `packages/billing/` and import from there, breaking the current circular-ish pattern
   - Tailwind config: where is the `@theme` defined? In `src/styles/global.css`? The tokens need to be in `packages/ui/` if UI is extracted
   - `astro.config.mjs` — Vite/Tailwind plugin path will need updating if UI moves to packages

7. **Report**: write to `docs/tasks/task-20260620-1718-explore-report.md` with:
   - **Skills Used**: list of skills loaded
   - **Current Architecture Summary**: 5-10 bullets
   - **Coupling Points**: table listing each `src/lib/*` file and what depends on it

   - **Tech Debt for Refactor**: list of issues to address during the refactor
